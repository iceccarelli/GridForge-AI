## What was deliberately NOT touched, and why

- **`gridforge/power/btm.py`, the `full_dlc_btm` scenario, and the "with behind-the-meter supply" figure on `/reference`.** These are the engine's own, already-reviewed treatment of behind-the-meter supply as *one priced, lead-timed relief rung* inside a real capacity study — explicitly distinguished in the repo's own `app/api/chat/route.ts` comments ("Behind-the-meter supply appears in a study only as one relief option for a grid constraint, priced and lead-timed like any other rung") and confirmed legitimate by `tests/test_one_company.py`. This is different from the forbidden pattern (BTM/microgrid/BESS pitched as the standalone product) and was left alone — no engine changes, per the standing constraint.
- **`lib/siting.ts`, `components/DelayDemo.tsx`, `components/LiveScenario.tsx`, `components/LiveMarket.tsx`, the `/intelligence` subscription plans and Stripe wiring.** `tests/test_one_company.py::test_no_price_hides_from_the_guard_by_being_written_in_cents` documents that these `GridForge Intelligence` tiers were deliberately moved into `lib/products.ts` and are now a legitimate, parity-tested part of the one catalogue — not a second checkout. Their BTM-vs-queue economics model is a real, tested feature, not leftover copy. This pass only rewrote the page-level marketing copy on `/intelligence` that overclaimed maturity or led with BTM; it did not touch the underlying model, its constants, or its Stripe/DB plumbing. A deeper pass reconciling `LiveScenario`'s on-page "BESS price arbitrage" demo (still linked from `app/page.tsx`'s "REAL DATA, NOT A MOCKUP" section) with the no-hardware-language constraint would be a reasonable follow-up — flagged, not fixed, given the size of that change relative to this task's scope.
- **`components/LoadSimulator.tsx`, `components/SystemFlow.tsx`, `lib/site.ts`'s unused `POWER_BLOCKS`-era constants.** Confirmed via `grep` that none of these are imported by any route (`app/page.tsx`'s own comments record why they were pulled from the money path in a prior pass). Dead code, not a live violation; left in place rather than deleted, since deleting unused components was not asked for and risks an unrelated diff.
- **`components/BackgroundReel.tsx`** (see table above).

## Images: technical notes

- Pack extracted to `time-to-power-image-pack-v1/` (git-ignored — added to `.gitignore` — so the extraction never gets committed; only production files under `public/images/ttp/*.webp` are tracked).
- `lib/ttp-images.ts` is the single registry (id → src/width/height/alt/caption), sourced from the pack's own `IMAGE_METADATA.json`.
- `components/TtpPhoto.tsx` is the one rendering path for pack images: always `next/image`, always carries `alt` + a `title` attribute with the honesty caption ("Reference photography — not a customer site; not measured evidence."), and prints a visible `<figcaption>` with the same text unless `hideCaption` is set for a small decorative crop (alt/title still carry it).
- `HeroReel` sets `priority` on the hero image only, per the pack's performance guidance; all other placements are default (lazy) `next/image`.
- No image replaces any of the protected components (`TimeToPower`, `TimeToPowerComparator`, `LoadSimulator`, `LiveConsole`, `LiveScenario`, `BindingConstraintInsights`, `SystemFlow`, `CommissionScreen`, `McpInstall`, `ApiPlans`, `EngagementLadder`) — verified by inspection of every file this pass touched.
